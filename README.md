# Keepsake — landing page

Адаптивний односторінковий лендінг дизайн-агенції Keepsake. Зверстано за макетом у Figma: [Keepsake - Responsive](https://www.figma.com/design/ZMpmNEBMsLPHJF7GyoHu2f).

**Демо:** https://USERNAME.github.io/landing-keepsake/

## Технології

- HTML5 (семантична розмітка) і CSS3, без фреймворків та UI-бібліотек
- Flexbox та CSS Grid
- CSS-змінні в `:root` для кольорів, шрифтів і відступів
- Mobile first: базові стилі для 375px, далі `@media (min-width: 768px)` та `(min-width: 1280px)`
- Шрифти Oswald, Open Sans і Dancing Script з Google Fonts (`font-display: swap`)
- Іконки — інлайн-SVG
- Зображення у форматі WebP

JavaScript у проєкті немає.

## Як що зроблено

**Розмітка.** Використано `header`, `nav`, `main`, `section`, `article`, `footer` і `form`. На сторінці один `h1`, далі `h2` для секцій і `h3` для карток. Змістовні зображення мають `alt`, декоративні — порожній `alt=""`.

**Токени.** Усі кольори, шрифти та основні відступи винесені в `:root` і використовуються тільки через змінні. Відступи (поля контейнера, відстань між секціями) перевизначаються у медіазапитах, тому розмітка не змінюється — змінюється лише значення змінної.

**Адаптивність.** Контейнер має максимальну ширину 1100px і центрується на широких екранах. Сітка перебудовується так: роботи — 1/2/3 колонки, послуги — 2×2 і 4 в ряд, клієнти — 2×3, 3×2 і 6 в ряд, журнал — 1 і 2 колонки.

**Мобільне меню без JS.** Прихований `checkbox` і `label` у ролі бургера. Стан `:checked` показує меню через селектор `~`, а іконка бургера замінюється на хрестик.

**Фільтр портфоліо без JS.** Радіокнопки стоять перед сіткою, чипси — це їхні `label`. Селектор `:checked ~` ховає картки, чия категорія (`data-category`) не збігається з обраною. Для «All» кількість карток залежить від ширини екрана: 5, 8 або 9.

**Ховер на картці.** Темний оверлей із назвою та категорією з'являється і при наведенні, і при фокусі з клавіатури (`:focus-visible`, `:focus-within`).

**Форма підписки.** Валідація email та обов'язковий чекбокс згоди працюють через HTML-атрибути. Стан помилки — через `:user-invalid`, успішна відправка — через `:target` (форма ховається, з'являється повідомлення). Реальної відправки немає.

**Header і кнопка «вгору».** Header зафіксований (`position: fixed`), кнопка «вгору» завжди на екрані.

## Доступність

- Усі інтерактивні елементи доступні з клавіатури, фокус видно
- Іконкові кнопки та соцмережі мають `aria-label`
- Поле email пов'язане з повідомленням про помилку через `aria-describedby`

## Відомі обмеження

Бургер зроблено на `checkbox`, а не на `<button>`, бо меню має працювати без JavaScript. Через це в нього немає `aria-expanded`. Також після тапу по пункту меню на мобайлі воно не закривається саме — тільки хрестиком.
